# 用户首次登录职位选择设计

- 日期：2026-07-22
- 状态：已实施并通过自动化与浏览器验证
- 项目：AI Tools web / RPA 项目管理系统

## 1. 目标与根因

用户端工作台目前只在 `/learning/me` 返回 `can_view_learning_report = true` 时显示“学习周报”。没有本地角色映射的账号默认被视为 `employee`，因此普通用户登录后看不到 RPA 学习情况记录入口。

本次在用户端登录流程中增加首次职位选择，让账号自行声明“实习生”或“正式员工”。职位首次保存后固定，用户不能自行切换；后续只能由具备现有人员权限管理能力的 HR 或老板修改。

## 2. 用户体验

用户登录页新增必选的“职位”下拉框：

- 实习生
- 正式员工

该字段只出现在用户登录页；管理员登录页保持不变。

用户输入账号、密码和职位后提交：

- 账号尚无角色映射时，密码验证成功后保存首次职位；
- 首次选择实习生时立即加入本周实习生名册，登录后显示“RPA 学习情况记录”，并可马上填写本周记录；
- 首次选择正式员工时保存 `employee` 角色，不显示学习记录入口；
- 账号已有角色映射时，选择与已固定职位一致则正常登录；
- 选择与已固定职位不一致时拒绝登录，提示“职位已固定，如需修改请联系管理员”。

用户端职位显示口径为：`intern` 对应实习生，`employee`、`hr`、`boss` 均对应正式员工。因此 HR 或老板使用用户端登录时应选择“正式员工”，不会改变其管理角色。

## 3. 后端职责

`POST /user/login` 新增必填字段 `employment_type`，只接受：

- `intern`
- `employee`

账号密码校验成功后，调用独立的首次职位确认服务。该服务负责：

1. 读取 `assets.db` 中的 `user_roles`；
2. 没有映射时创建 `UserRole`；
3. 追加 `RoleChangeLog`，来源记为 `self_selection`；
4. 首次选择 `intern` 时确保本周名册头存在，并将用户加入本周 `WeeklyRoster`；
5. 在同一 SQLite 事务中提交角色、审计日志和本周名册成员；
6. 已有映射时只校验职位，不更新任何数据。

首次选择正式员工也必须创建显式 `employee` 映射，从而区分“已经固定为正式员工”和“尚未首次选择”。

并发首次登录依赖 `user_roles.user_id` 主键及本周名册唯一约束防止重复。发生唯一约束竞争时回滚当前事务，重新读取已保存职位：一致则按幂等成功处理，不一致则返回职位冲突。

## 4. 名册与统计口径

首次选择实习生“立即加入”是现有周名册冻结规则的一个明确例外，仅用于账号首次职位确认。该用户从当前周开始计入：

- 当周应提交实习生人数；
- 当周未提交人数；
- 用户端本周 RPA 学习记录填写资格。

管理员在“人员权限”中将正式员工调整为实习生时，仍沿用现有规则，从下一未冻结周开始进入名册。本次不改变管理员角色调整的周名册语义。

学习统计继续只计算最新有效正式提交；草稿、缺失、退回修改中和退回逾期记录的统计口径不变。

## 5. 权限与数据边界

- 用户只能在尚无角色映射时固定一次职位；不能通过重复登录覆盖角色；
- 用户端请求不能自行声明 `hr` 或 `boss`；
- 后续职位调整继续由 HR/老板通过现有角色管理接口完成；
- 管理员入口登录不读取或写入 `employment_type`；
- 所有新增写入仅发生在本地 `backend/var/assets.db`；
- 共享 MySQL `users` 继续只读，不新增字段、不修改数据。

## 6. 接口响应与错误处理

用户登录成功响应继续返回既有 `user_id`、学习令牌和学习角色，并新增规范化后的 `employment_type`，供前端保存当前界面状态或展示。

- 缺少职位或职位值非法：返回 `422`；
- 账号或密码错误：保持现有 `401` 响应，且不泄露职位是否已经设置；
- 已固定职位与本次选择不一致：返回 `409`；
- SQLite 写入失败：回滚角色、审计和名册，不出现部分成功；
- 登录失败时前端保留用户输入并显示后端返回的中文提示。

## 7. 前端变更

`LoginView.vue` 在用户端配置中启用职位选择：

- 使用原生 `select`，保持现有表单样式；
- 默认值为空，强制用户明确选择；
- 登录请求体增加 `employment_type`；
- 管理员端不渲染该字段，也不发送该字段；
- 登录成功后的学习 profile 仍以 `/learning/me` 为权威来源。

用户工作台继续依据 `can_view_learning_report` 显示入口。首次实习生已经被写入角色并加入当周名册，因此无需在前端放宽权限或硬编码显示。

## 8. 验证范围

后端自动化测试覆盖：

- 用户登录缺少或传入非法职位时失败；
- 首次选择正式员工创建显式 `employee` 映射；
- 首次选择实习生创建角色、审计记录和本周名册成员；
- 首次实习生登录后 `/learning/me` 允许查看并提交本周记录；
- 相同职位重复登录幂等成功且不重复审计或名册；
- 不同职位重复登录返回 `409` 且不改角色；
- HR/老板在用户端选择正式员工可登录且不丢失管理角色；
- 管理员登录无需职位且保持原响应行为。

前端自动化测试覆盖：

- 用户登录页显示职位选择并要求选择；
- 用户登录请求携带规范化职位；
- 管理员登录页不显示也不发送职位；
- 实习生能力返回后用户工作台显示 RPA 学习入口。

最终执行完整后端测试、前端测试、生产构建，并重启本地后端验证新登录流程。
